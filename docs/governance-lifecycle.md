# 稿件与账号生命周期整改

日期：2026-09-29。遵循用户确认的规则；生产数据只做状态核查，不用真实账号执行删除、封禁或移交测试。

## 已定位的两个直接缺陷

N-754AEB26 是 OE 自己的零版本已撤回草稿：没有提交版本、审稿意见、须知确认。旧删除逻辑额外要求状态为 draft，因此作者先撤回后就不能删除。现在按“从未正式提交”判断，允许 draft／withdrawn 的零版本稿件从列表和详情删除；正式提交过的稿件不按草稿删除。

申请页只加载 pending 申请的候选账号，却渲染 approved 历史申请，导致 face(undefined) 崩溃。现在按持久账号主键加载全部可见申请的候选和认可人，显示其当前独立昵称与 UID；昵称不是关联键。已注销账号显示占位名称，不让一条历史记录毁掉整页。

## 稿件状态与处理区别

| 决定 | 修改与后续操作 | 公开行为 |
| --- | --- | --- |
| withdraw／withdrawn | 作者主动撤回，可保存修订、重新提交；提交时生成新版本 | 未发表稿件不公开 |
| 作者撤稿／retracted | 可修订并重新审阅；新版本录用后由作者安排发表 | 保留撤稿说明，不展示正文 |
| revision | 保存独立 workingDraft；提交时产生新版本和须知确认 | 不自动公开修订 |
| reject | 原稿锁定；不能请求修改或从此记录创建关联重投；仍可走分级上诉 | 不发表 |
| reject & resubmit | 原稿锁定；创建一个关联的新草稿，重新走完整投稿流程 | 新稿通过后由作者安排发表 |
| ban | 永久下架；不开放修改、发表或关联重投 | 从公开 API 投影移除 |
| temporary down | 可保存修订并交给达到复核要求的审稿人；通过后作者重新安排发表 | 复核及发表前保持隐藏 |
| nothing | 不改变内容、公开状态或添加争议标签 | 保持原状 |
| caution | 允许公开作者进一步陈述，并发起更正审阅 | 顶部争议提示；更正通过并由作者发表前，保留原公开版本 |

提交的历史版本不被暂存草稿替换。争议更正另存 publicSnapshot，原公开版本与审阅版本独立。

暂时下架的作者待办限期为 30 天。暂存不能解除期限；正式交回审稿队列后停止作者计时；再退修或录用等待作者处理时重新给 30 天。作者设置定时或正式发表后解除期限。后台超期任务转永久下架，清除可编辑草稿；实际处理由每分钟 cron 执行，有队列等待。

旧举报 remedy=notice 映射 caution，remedy=retract 映射 ban；已存在历史“retracted”记录不批量改写，避免误认作者撤稿。

## 账号管理

- 普通用户、临时及常驻 Reviewer 没有“账号与权限”入口或资料接口访问资格。
- AE 及以上可搜索独立昵称、独立 UID、查看独立身份资料与积分；每页最多 50 个匹配账号，不把当前操作者硬塞入搜索结果。
- Editor 及以上按原因搜索社区昵称／UID，查询记录进入审计；查询结果可显示被定位的社区面。独立资料页仅列出该独立身份的文章，防止默认合并两套身份。
- Editor 及以上仅能封禁和删除严格低于自己等级账号的内容。不能处理自己、同级或上级。临时封禁选截止时间，永久封禁或解除封禁须写理由。
- 封禁阻止投稿、审核、权限、互动等写入，保留读取自己通知、标为已读及自主注销的途径；到期按截止时间判断自动恢复。已领取任务有限量同步释放，剩余由后台释放。
- 删文章采用永久下架并保留作者可查看的处理记录；删评论进入 removed，不能通过作者编辑重新公开。永久注销则清除相关业务记录。

## 永久注销与最高权限移交

第一次明确确认由本人或 OE 请求短时一次性确认票据。第二次要求输入目标社区 UID。服务器重新检查执行人权限、目标当前角色和资料版本；票据只可消费一次，5 分钟到期。

执行时立即停用账号、撤销会话／登录交换票据、移除该账号文章与评论的公开数据库投影。随后由 account_erasure 队列分批清理自己的内容、关联互动、通知、申请、积分和附件引用；他人稿件中的审批身份匿名化，解除当前任务分配；最后删除用户实体和登录绑定。任务恢复由数据库持久化队列保证，纳入业务备份。

唯一 OE 不能直接注销。OE 可两次确认后将权限移交给另一有效账号，自己成为 Editor，再走注销。数据库唯一索引和同事务角色变更保持唯一 OE；原指定 GitHub 账号重新注册也不能夺回已有 OE。

本人注销成功会清理本机该账号的编辑草稿、会话摘要、通知缓存和已读入的公开内容缓存。后台不能擦除他人保存的公开副本、旧构建和离线副本，也不能改写运营者已导出的旧备份；恢复旧备份前必须重新处理已经执行的数据删除。

## 消息与操作响应

采用现有 TanStack Query Core 请求去重与短期缓存：

- 登录验证后非阻塞预取自己的通知；悬停和键盘聚焦消息入口也预取。
- 消息分类只过滤同一份数据，不为每个分类再发请求。
- 60 秒会话摘要保存自己的通知，刷新先显示，再更新；不缓存其他人的审稿队列或身份审计。
- 网络请求被会话 token 绑定，退出后迟到响应不得重新写入私密状态。
- 稿件提交和状态按钮增加执行中锁定，避免重复点击。
- 写操作确认返回即更新提示，后台二次读不延迟成功提示。

审稿回合、待办时限和历史决定的结构参考 [OJS 官方审稿文档](https://github.com/pkp/pkp-docs/blob/main/learning-ojs/editorial-workflow/en/review.md)。NARV 仍由一名有资格审稿人录用，明确邀请重投时才新建关联稿件。

参考：[TanStack 预取与路由整合](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching)。按生命周期组织管理权限、状态、理由和用户资料入口，参考 [Discourse 状态与权限文档](https://meta.discourse.org/t/understanding-user-statuses-roles-and-permissions/35171) 与 [官方管理控制器](https://github.com/discourse/discourse/blob/main/app/controllers/admin/users_controller.rb)。NARV 的角色层级、双身份和投稿决定继续按自己的规则，不照搬 Discourse 的公开管理员标识或用户模拟功能。

## 验收与仍有的边界

61 项自动测试；原有完整原型浏览器流程、数据库联调流程、生命周期浏览器流程、搜索移动界面均验证通过。专门验证撤回零版本草稿删除、已通过申请改名、关联重投去重、争议更正不提前换正文、临时下架时限、严格等级封禁与删评、两次注销及不可重放、原子 OE 移交、消息分类去重与人为 1500 ms 延迟下的缓存显示。

cron 计划查询合并为一条，分支处理注销／超期／任务释放；普通定时发表与支持奖励满批仍维持 49 条 SQL 以内，不超过免费 D1 每次 50 条语句。

公开文章页面现在读取边缘缓存的实时投影校验状态，404 会清除页面缓存；正文校验前展示加载状态。首页／搜索仍主要走 Pages 静态包。下架、注销和更正后的旧静态文件、搜索块、图片要等下一次 Pages 构建清理；15 分钟调度可能延迟，不能承诺立即全网消失。公开 API 也可能有最多约 60 秒缓存。需要在后续优先解决静态撤回同步，并观察免费动态请求配额。
