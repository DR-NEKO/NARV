# 容量与并发改造

目标：5,000 人同时在线，以阅读／搜索为主，少部分人登录互动。零费用约束继续有效。

## 改造顺序与验收

1. 公共阅读通过 GitHub Pages 的静态内容包和 CDN；匿名浏览不拉取私人 bootstrap，页面切换不重复请求整个站点。
2. 为私人数据增加索引，只读取当前用户、当前页面或当前稿件；历史版本和配图按需读取。
3. 将全站版本锁改成记录版本锁：同一稿件冲突会拒绝，不同用户不同稿件可并行操作。
4. 图片按内容哈希去重，文本和版本压缩；维持明确的储存限额和用量提示，不自动切换付费。
5. 工作台缓存、分页和加载状态；统一头像上传等控件的外观与反馈。
6. 本地 5,000 虚拟读者压测、交叉账号写入和冲突测试，并完成小规模线上验证。报告区分本机结果、云端实测和平台保障；不得把本机压测称为 Cloudflare/GitHub 的容量保证。

## 免费服务的边界

Workers Free 每天 100,000 次动态请求，D1 每天 5,000,000 行读取／100,000 行写入；单个 D1 免费数据库最大 500 MB。GitHub Pages 每月有 100 GB 软带宽额度。边缘缓存命中仍计入 Worker 请求额度，因此 5,000 读者的常规阅读应直接走 Pages 静态资源。

公开索引会定时同步；新发表文章的直接链接仍可从只读 API 获取。用户操作的结果即时反馈，公共索引允许同步延迟。动态读写超过日额度仍会失败，不能承诺 5,000 人持续高频互动免费无限运行。
